# V.Adapter 服务端插件 · 设计说明

> 本文档描述 V.Adapter 服务端插件的设计目标、形态关系、数据流、功能范围、目录结构、
> 安装与客户端配置，以及酒馆自带生图扩展的相关事实。作为设计/架构说明，文中结论均已确定。

---

## 概述

将 V.Adapter 的协议适配能力作为酒馆服务端插件运行：酒馆启动时插件随之启动，客户端对接方式与 Go 原版一致（仍连接 `IP:8888`）。

此前：用户自行运行 exe，占用 8888 端口。
此后：由酒馆托管（酒馆关闭时插件随之关闭），无需管理独立进程。

---

## 三种形态对比

| | ① Go 原版（现有） | ② 前端 UI 扩展 | ③ 服务端插件（本目录） |
|---|---|---|---|
| 形态 | 独立 exe | 酒馆前端扩展 | 酒馆服务端插件 |
| 对外协议 | NovelAI 协议 | 不对外（自行出图） | NovelAI 协议 |
| 客户端接入 | URL 填 `IP:8888` | 无需接入 | URL 填 `IP:8888`（与①完全一致） |
| 是否独立进程 | 是 | 否 | 否（随酒馆启动/关闭） |
| 管理面板 | 有 | 有 | 有（沿用原版界面） |

**设计决策：对外仅提供 NovelAI 协议面。** 若新插件再对外提供 OpenAI 格式接口，则①中"Open→NAI 转换"的能力被架空。因此：对外仅识别 NAI 协议，内部转换为 OpenAI 上游。

## 数据流

```
客户端（酒馆助手 / 任何 NAI 协议客户端）
   │  POST /ai/generate-image（NovelAI 格式 JSON + Bearer key）
   ▼
【V.Adapter 插件】监听 8888
   │  校验 key → 按客户端 input 原样转成 OpenAI 兼容请求
   ▼
上游生图 API（OpenAI 兼容；标准接口失败自动转聊天接口兜底）
   │  拿到图片
   ▼
去水印（聊天链路图）→ 打包装进 ZIP → 原路返回
   ▼
客户端拿到 ZIP，解压出图
```

## 功能清单

功能从 Go 版 1:1 移植，无裁剪：

- **NAI 端点三件套**：`/ai/generate-image`（回 ZIP）、`/ai/user/subscription`（测试连接显示"Free"）、`/ai/encode-vibe`（404，不支持）
- **两个非标准扩展参数**（查询串，标准 NAI 客户端不受影响）：`raw=1` 直出图片字节不套 ZIP 壳；`expand=1` 先把 `input` 交给聊天模型扩写为完整画面提示词再出图
- **key 校验**：`nai_key`（默认 `v-adapter-8888`，清空则任意 key 可调）
- **上游调用三件套**：优先 b64_json 解码 → 否则下载 url → 携带 negative_prompt 失败时自动去除后重试
- **聊天接口兜底 + 熔断**：标准接口无法获取图片时自动转聊天接口；连续 3 次故障熔断 30 分钟（直接走聊天，不再等待标准接口）
- **尺寸处理**：客户端传值原样使用（clamp 64~2048）；上游拒绝尺寸时回退默认尺寸重试
- **右下角水印抹除**：9×9 均值模糊 × 6 轮（仅聊天链路的图带水印）
- **角色转译**：面板上输入描述直接出图
- **生成记录**：最近 200 条（时间/尺寸/链路/耗时/结果/提示词/错误）
- **管理面板**：运行总览 / 角色转译 / 生成记录 / 设置中心
- **设置热生效 + 持久化**：面板修改立即生效，重启不丢失

> **画风不在此服务内。** 原版的 `style.go`（14 个画风预设 + 自定义）已移除：
> 经本服务转发的请求按客户端送来的 `input` 原样发出，不附加任何风格前缀。
> 画风由消费方自行决定 —— V.Canvas 在「提示词」页配置，第三方生图插件用其自带入口配置。

## 目录结构

```
server-plugin/            交付时整体放入酒馆 plugins/ 目录（重命名为 V.Adapter）
  方案说明.md              本文档
  index.js                插件入口（向酒馆声明身份、启动与退出方式）
  panel.html              管理面板（取自 Go 版）
  LICENSE                 原许可（保留 VILK 署名）
  lib/
    nai.js                NovelAI 协议端点（收 NAI 格式、回 ZIP）
    pipeline.js           上游调用（三件套 / 兜底 / 熔断）
    translate.js          角色转译
    watermark.js          去水印
    zip.js                ZIP 打包
    settings.js           设置（读写 data/settings.json）
    genlog.js             生成记录
    server.js             内嵌 HTTP 服务（组装路由 + CORS），已完成
    admin.js              管理端点（面板接口 + 密码），已完成
  data/                   运行时自动生成（settings.json），不含在交付物中
```

## 安装

1. 将 `server-plugin` 文件夹放入酒馆 `plugins/` 目录，重命名为 `V.Adapter`
2. 酒馆 `config.yaml` 中将 `enableServerPlugins` 改为 `true`（默认 false）
3. 重启酒馆 → 浏览器打开 `http://127.0.0.1:8888`，即管理面板

> 采用独立端口的原因：酒馆服务端存在 CSRF 防护，第三方客户端（酒馆助手等）直连酒馆插件路由会被拦截 403。插件自行监听 8888 可规避该限制，同时保留①的对接方式。

---

## 客户端配置

- **URL**：`http://<服务器IP>:8888`（无需带 `/ai`，客户端自动补全）
- **Key**：管理面板中设置的 `nai_key`
- **模型**：任意选择（服务端忽略）
- **vibe 参考图**：不支持，请勿启用

## 设计决策

以下结论已确定：

1. **命名**：插件文件夹为 `V.Adapter`，面板显示名保持 "V.Adapter"。
2. **端口**：沿用 8888。若 Go 版常驻运行会产生冲突，需先停止 Go 版。
3. **前端 UI 扩展（`/vgen`）保留**：两种入口互不冲突，可同时存在。
4. **面板密码功能保留**：首次免密、可设密码（详见服务端插件 README 的登录说明）。
5. **引擎配置由本服务端持有**：上游、模型、默认尺寸、生图链路以本服务端（`:8888`）为唯一权威。
   酒馆前端扩展形态另有一份独立配置，只作用于它自己的 `/vgen` 与角色转译；经 `:8888` 出图的
   V.Canvas 与第三方 NAI 插件读的是本服务端这份。两条管道各有一份配置，不构成重复，
   原因是两条管道的必经环节不同。
6. **画风不在本服务内**：原版的 `style.go` 已移除。理由是画风属于「怎么画」中
   由消费方决定的部分 —— V.Canvas 有独立的「提示词」页（正面质量 / 负面 / 画风），
   第三方插件也有各自的入口；服务端再存一份，只会造成"配了却没生效"的困惑。
   经本服务转发的请求按客户端送来的 `input` 原样发出。
7. **自动出图不属于本插件**：监听 AI 回复、解析标记、就地插图由 V.Canvas 承担。
   本插件只负责「怎么画」，不监听 `MESSAGE_RECEIVED`。

## 已知限制与事实

酒馆自带"图像生成"扩展的两个源地址均为硬编码（NovelAI 源固定访问 `image.novelai.net`，OpenAI 源固定访问 `api.openai.com`），因此其魔法棒按钮无法指向本插件——这并非能力缺失，而是酒馆未提供相应接口。

可对接的范围：
- 酒馆助手的自定义生图（已安装本插件时）
- 任何支持自定义 NovelAI URL 的客户端
