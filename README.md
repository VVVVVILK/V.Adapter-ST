# V.Adapter · 酒馆生图引擎

> 把一句话变成一张图。V.Adapter 内置于酒馆页面，直接对接 OpenAI 兼容生图 API——装好即用，无需独立服务、无需端口、无需 NovelAI 渠道。

它是酒馆里的出图引擎：上游画师（OpenAI 兼容生图 API）负责作画，V.Adapter 负责把「描述」变成「请求」、把「返回」变成「图片」——标准生图接口不可用时自动转聊天模型兜底，右下角水印顺手抹除，画完的图以画廊形式落进聊天。它不管「什么时候该画」——那是 V.Canvas 的活；它只管画得成、画得干净、画得有记录。

> 移植自 V.Adapter v1.1.4（Go，作者 **VILK**，MIT License），核心逻辑逐字移植。

## 它能做什么

### 🎨 装好即用的出图引擎
- **无需独立进程**：扩展自身即为出图引擎，安装后即在酒馆内出图——没有独立 exe、没有独立端口、不用配置 NovelAI 渠道。
- **核心逻辑逐字移植**：协议转换、描述转译、水印抹除、设置持久化、生成记录，各模块与 Go 原版一一对应。

### 🔁 生图链路：标准优先，自动兜底
- **四档链路可选**：`auto`（标准接口优先、失败自动转聊天兜底，反代场景推荐）/ `off` / `chat_only` / `openai`。
- **熔断不卡死**：标准生图接口不可用时自动降级到聊天模型兜底，出图不中断。
- **远程图兜底展示**：聊天兜底拿到的远程图片链接不支持本地下载时，直接引用原链展示（该图不做水印抹除）。

### 🪄 一句话出图：角色转译与 /vgen
- **角色转译页**：输入一句描述 → 自动转译为完整提示词 → 出图。
- **`/vgen` 命令**：可绑快速回复；`translate=false` 直接把内容当提示词，`size=832x1216` 指定尺寸。
- **结果进聊天**：以「角色消息 + 图片画廊」插入（与酒馆原生生图一致），图片自动存入酒馆用户数据目录。

### 🧹 水印自动抹除
- 右下角水印自动抹除（9×9 均值模糊 × 6 轮，Canvas 实现），与 Go 原版算法一致。

### 📋 生成记录与完整面板
- **运行总览**：服务状态、当前生效配置（Key 脱敏）、最近生成记录。
- **生成记录**：最近 200 条，随时回看。
- **设置中心**：上游 API、模型、默认尺寸、生图链路；改动即时持久化，保存失败回滚并说明原因。

### 🔗 双管道配置，各归其位
- **① `:8888` 协议端口**：供 V.Canvas、第三方 NAI 插件、外部客户端使用 → 配置在**服务端插件**（`<SillyTavern>\plugins\V.Adapter\data\`，在 `http://127.0.0.1:8888` 面板维护）。
- **② 扩展内部**：供本扩展的 `/vgen` 命令、角色转译出图使用 → 配置在本扩展管理面板。
- 两条管道的**必经环节不同**，配置只能落在该管道的必经环节上，各存一份、互不通用；改错位置不会生效。
- **画风已移除预设**：由消费方自行决定——V.Canvas 在「提示词」页配置，第三方生图插件用其自带入口配置。经 `:8888` 转发的请求按客户端送来的 `input` 原样发出，本服务不附加任何风格前缀。

### 🤝 与 V.Canvas 分工明确
- 本扩展负责**「怎么画」**：上游对接、协议转换、去水印、生成记录、`:8888` 协议端口。
- 监听 AI 回复自动出图（**「什么时候画、在哪显示」**）由 **V.Canvas** 承担，本扩展不再提供——互不重复，各司其职。

## 小贴士
- **反代场景选 `auto`**：标准接口失败自动转聊天兜底，流程不卡。
- **留意 CORS**：扩展跑在浏览器里，直连上游需上游允许 CORS（返回 `Access-Control-Allow-Origin`）；自建反代（如 zai2api-http）加一行 CORS 头即可，否则请换支持 CORS 的中转。
- **配置按管道存**：给 `/vgen` 改配置去本扩展管理面板，给 V.Canvas 改配置去 `:8888` 服务端插件，别改错地方。
- **画风不在这里配**：本服务不附加画风，交给消费方（V.Canvas「提示词」页）决定。

## 安装

### 一、扩展本体

1. 打开酒馆 → 顶部「扩展」面板（三个方块图标）
2. 点「安装扩展」
3. 粘贴本仓库的 git 地址（`https://github.com/<USERNAME>/V.Adapter.git`）→ 安装
4. 完成后扩展列表出现「V.Adapter」

**无法访问 GitHub 时（本地安装）**：解压发布包（`V.Adapter-1.1.4-src.zip`），将整个
`V.Adapter` 文件夹放入 `<SillyTavern>/data/<user-handle>/extensions/`，重启酒馆即可。

### 二、安装服务引导器（一次性）

酒馆只在进程启动时加载 `plugins/` 下的服务端代码，也不为服务端插件提供安装入口，
所以引导器需要手动放置一次。放置后**不再需要随版本更新**——服务端实现本身位于
扩展目录内，随「安装扩展」一起走。

- Windows：编辑 `install-loader.bat` 里的 `ST=`，双击运行
- Linux / macOS / Termux：`sh install-loader.sh`（可用 `ST=/path/to/SillyTavern` 指定）

脚本把 `bootstrap/` 复制到 `<SillyTavern>/plugins/V.Adapter/`，已有的 `data/` 保持不动。
随后确认 `config.yaml` 里 `enableServerPlugins: true`，**重启酒馆一次**。

### 三、启动协议服务

扩展抽屉的三行：

```
V.Adapter      v1.1.4-st.1
   协议服务              [ 已停止 / 运行中 · 0.0.0.0:8888 ]
   [ 启动协议服务 ]
   [ 重载实现 ]
   [ 打开管理面板 ]
```

- **启动协议服务**：载入位于扩展目录内的 `server-plugin/`，监听 `:8888`
- **重载实现**：先释放端口再重新载入，用于更新扩展后立即生效（**无需重启酒馆**）
- 运行数据与代码分离，始终存放在 `<SillyTavern>/plugins/V.Adapter/data/`

更新流程：点「安装扩展」覆盖扩展 → 在抽屉点「重载实现」。

## 配置（一次性）

打开扩展抽屉 →「打开管理面板」→「设置中心」：

| 配置 | 说明 |
|---|---|
| API 地址 | OpenAI 兼容生图接口 base url（通常以 `/v1` 结尾） |
| API Key | 上游密钥 |
| 模型名 | 上游生图模型 |
| 默认尺寸 | `宽x高`，如 `832x1216` |
| 生图链路 | `auto`（标准接口优先、失败自动转聊天兜底，反代场景推荐）/ `off` / `chat_only` / `openai` |

> **跨域说明**：扩展运行在浏览器里，直连上游 API 需要上游允许 CORS（返回
> `Access-Control-Allow-Origin`）。自建反代（如 zai2api-http）加一行 CORS 头即可；
> 若上游不支持 CORS，标准接口将无法在浏览器使用，请换用支持 CORS 的中转。
> 聊天兜底链路拿到的远程图片链接不支持本地下载时，会直接引用原始链接展示
> （该图不做右下角水印抹除）。

## 配置分两处（引擎配置的归属）

引擎配置（上游 API、模型、默认尺寸、生图链路）按管道各存一份，互不通用：

| 管道 | 谁在读 | 配置位置 |
|---|---|---|
| ① 经 `:8888` 端口 | V.Canvas、第三方 NAI 插件、外部客户端 | **服务端插件**：`<SillyTavern>\plugins\V.Adapter\data\`，在 `http://127.0.0.1:8888` 面板维护 |
| ② 本扩展内部 | 本扩展的 `/vgen` 命令、角色转译出图 | 酒馆扩展设置（`extension_settings['v-adapter']`），在本扩展管理面板维护 |

原因是两条管道的**必经环节不同**，配置只能落在该管道的必经环节上，否则不会生效。

> **画风不在此列。** 本扩展已移除画风预设：画风由消费方自行决定 ——
> V.Canvas 在「提示词」页配置，第三方的生图插件用其自带入口配置。
> 经 `:8888` 转发的请求按客户端送来的 `input` 原样发出，本服务不附加任何风格前缀。

## 抽屉与管理面板

**抽屉**（安装、启停都在这里）：

```
V.Adapter      v1.1.4-st.1
   协议服务        已停止 / 运行中 · 0.0.0.0:8888
   [ 启动协议服务 ]
   [ 重载实现 ]
   [ 打开管理面板 ]
```

**所有参数都在面板里**：

| 页 | 内容 |
|---|---|
| 运行总览 | 服务状态、当前生效配置（Key 脱敏）、最近生成记录 |
| 角色转译 | 描述 → 出图 |
| 生成记录 | 最近 200 条 |
| 设置中心 | 上游 API、模型、默认尺寸、生图链路 |

配置改动即时持久化：开关或输入框失焦即写入；保存成功提示「已保存并生效」，
保存失败则回滚并说明原因（如正则表达式不合法）。

> 职责边界：本扩展负责「怎么画」（上游对接、协议转换、去水印、生成记录、
> `:8888` 协议端口）。监听 AI 回复自动出图属「什么时候画、在哪显示」的范畴，
> 由 **V.Canvas** 承担，本扩展不再提供该功能。

## 命令 /vgen（可绑快速回复）

```
/vgen 一只橘猫趴在窗台上晒太阳          ← 描述，自动转译成提示词后出图
/vgen translate=false 1girl, ...       ← 直接把内容当提示词出图
/vgen translate=false size=832x1216 1girl, ...
```

出图结果以「角色消息 + 图片画廊」的形式插入聊天（与酒馆原生生图一致），
图片自动存入酒馆用户数据目录。

## 与原版（Go 独立服务）的对应关系

| 原版 | 扩展版 |
|---|---|
| 独立进程监听 `0.0.0.0:8888` | 内置于酒馆页面，无需端口 |
| NovelAI 渠道填 URL 对接 | 无需配置，扩展直接出图进聊天 |
| `POST /ai/generate-image` → ZIP | 扩展内部函数调用 → 图片存入酒馆并插入消息 |
| 管理面板 `http://ip:8888/` | 扩展抽屉「打开管理面板」（UI 1:1 保留） |
| `data/settings.json` 持久化 | 酒馆扩展设置持久化（随酒馆配置文件） |
| 面板密码保护服务端 | 面板运行于用户本地浏览器中，密码功能保留但不再需要 |

原版核心逻辑逐字移植：`qwen_client.go`→`lib/pipeline.js`、`translate.go`→`lib/translate.js`、
`watermark.go`→`lib/watermark.js`（Canvas 实现，同样 9×9 均值模糊 × 6 轮）、
`settings.go`→`lib/settings.js`、`genlog.go`→`lib/genlog.js`、
`admin.go`+`auth.go`→`lib/virtual-api.js`。
原版的 `style.go`（画风预设）不再移植。
